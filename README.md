# 安燃

一个插件，统一提供安燃原生桌宠、各 Agent 使用的运行器和连接配置。不需要另装第二个 MCP 产品或 `pet-plus`，也不需要手动解压运行器 ZIP。

## 在 Kimi 中使用

安装并启用“安燃”插件后，在对话中发送“安装安燃”。Kimi 会发现并复用已有正式实例；确认不存在时才创建原生 DIY 桌宠并发布交互页面。插件详情页的“使用”按钮本身不会创建桌宠。

单击跳跃，双击施法，连续点击触发升级反应，左右拖动切换动作；Kimi 执行任务时，安燃随任务状态变化。

## 在其他 Agent 中使用

直接对已经装有安燃插件的 Agent 说“把安燃连接到 vBuddy”或“把安燃连接到 WorkBuddy”。统一入口是 `skills/anran-pet/scripts/install_anran.py connect --host <宿主>`：

- 原生安装入口先把运行器和资源复制到 `~/Library/Application Support/Anran/versions/<版本-哈希>/`，检查后切换 `current`；宿主只引用 `current/anran`，上一代保留用于回滚。安装完成后，源插件目录或 Kimi 安装目录不再是运行依赖。
- WorkBuddy：由 Agent 使用 `--apply` 更新官方 MCP 数据文件和用户 hooks，只保留一个安燃项，不覆盖无关连接器或配置。
- vBuddy、千问、豆包：Agent 读取统一入口生成的配置，并通过对应宿主的官方连接器界面填写；用户不需要再安装另一份插件。

其他 Agent 中看到的“安燃连接器”只是同一产品的注册，不是第二个安燃产品。所有受支持宿主共用这些体验：宿主客户端启动并连接时显示安燃；任务结束或 stdio 断开不再关闭，宿主客户端退出时才关闭；右键可打开对应 Agent 或关闭桌宠；拖动后保存位置，屏幕变化只收回到可见边缘，不自动回中央。

Kimi 插件详情页的“更新”只更新 Kimi 自己的插件副本，不再是 WorkBuddy 或其他宿主的更新前置步骤。各宿主通过同一个安燃安装入口升级稳定目录中的运行器。

## 保护与边界

- 已有正式实例直接复用；多个或身份不明的候选会停止，不猜选、不删除。
- 页面已有用户修改时不覆盖；测试实例单独登记并精确清理。
- 运行器、资源或连接失败会明确报错，不输出不可用的假配置。
- 安装或配置写入失败会恢复旧配置和旧 `current`，并保留上一代安装。
- 只使用官方桌宠接口、官方连接器界面和 WorkBuddy 官方 MCP 数据文件；不修改任何宿主程序包。
- 插件安装、离线测试和进程启动均不等于真实视觉与交互验收，未实测项目必须单独说明。

## 从 GitHub 安装

尚未安装插件时，可把仓库链接发给 Kimi，并说“安装并启动这个仓库里的安燃”。Agent 会连续完成插件导入、正式实例发现与复用或首次创建、页面发布，不停在登记或安装回执。

## WorkBuddy 任务事件与气泡（0.2.5）

通过 WorkBuddy 官方用户 hooks（UserPromptSubmit／PreToolUse／Stop／Notification）把任务状态提供给安燃。卡片标题显示规范化空白后最多 30 个字符的任务片段，正文分别显示“正在处理”“任务完成”或“等你回复后我继续”；完成、等待确认和错误只改变状态图标，不改变整张卡片材质。任务中卡片持续到任务结束。任务片段只用于本机气泡，不上传、不写事件正文日志；完整提示词和工具正文不进入桌宠。缺少任务标题时回退为“新任务”，缺少完成状态时回退为“任务完成”。

`connect --host workbuddy --apply` 先安装到安燃稳定目录，再同时注册 MCP 与 hooks。重复执行会替换安燃自己的配置并保留其他连接器和 hooks；需要随包运行器 0.2.5+，首次接入或修改 hooks 后重开 WorkBuddy 会话。连接、任务中、完成、等待确认和错误共用 Kimi 原生风格的圆角卡片；真实桌面视觉与各宿主事件仍须分别验收。
