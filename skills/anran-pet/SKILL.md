# 安燃桌宠

本插件提供已经批准的安燃图集、清单和交互页面。插件安装后不会自动弹出桌宠；用户提出安装请求时，按下面流程由 Agent 调用官方 `Widget.installPet` 完成。

## 用户只给 GitHub 链接时

用户说“安装并启动这个仓库里的安燃”并附上仓库链接，即同时要求导入插件、安装插件和创建独立安燃。先通过当前宿主官方支持的入口完成插件导入与安装，再读取本技能并连续执行下面的全部步骤。不要只登记到个人页签，不要要求用户再点击安装，也不要在插件安装成功后停下。插件若需重启才能在后续会话加载，应单独如实报告；不得擅自重启，也不得把重启提示当成本次桌宠已经创建的证据。

## 安装

1. 确认当前工作区，运行 `python3 <本技能目录>/scripts/install_anran.py stage --workspace <当前工作区绝对路径>`。脚本返回 `packagePath` 和素材哈希。已有非空同名暂存目录会停止，避免覆盖。
2. 调用 `Widget.installPet`，把上一步的 `packagePath` 原样传入。成功只代表原生包被接受，不代表交互页面已发布或桌面效果已验收。
3. 调用 `Widget.read` 读取新安燃的 `workspaceRoot`，再检查其中的 `index.html`。`Widget.installPet` 会为新桌宠生成默认页面；确认这份页面正是本次安装生成、没有用户修改后，运行 `python3 <本技能目录>/scripts/install_anran.py finalize --widget-root <workspaceRoot> --overwrite`，用插件内的已批准页面替换它。
4. 如果 `index.html` 是用户已有或自行修改的页面，保留该文件并先询问；只有用户明确同意覆盖时才加 `--overwrite`。仅重装素材不需要覆盖交互页面。
5. 再读回 `pet.json`、图集和 `index.html` 哈希。需要检查真实桌面时，遵守当次桌面观察授权；没有授权就只报告离线安装结果，请用户观察实际桌面。

## 测试副本

需要验证插件而不影响正在使用的安燃时，在 `stage` 加 `--pet-id anran-plugin-preview`。测试结束后删除这个测试桌宠，不把它当作用户正式角色。

## 出现问题时

- 暂存目录非空：停止并核对现有文件，不强制覆盖。
- 原生安装失败：原样报告失败项，检查包结构和当前宿主限制。
- 页面已存在：保留用户修改，未经确认不覆盖。
- 插件目录无法定位：重新从已加载技能的位置解析插件根，不猜本机固定路径。
- 真实窗口、输入或播放未观察：明确列为未验收，不用安装回执代替。

## 内容边界

角色身份、配色、动作与当前资产属于安燃项目。本技能只负责分发和安装，不包含通用桌宠制作方法，也不要求用户安装 `pet-plus` 才能使用。
